# SPEC-IDEAS — 4 обязательные фичи VPN-магазина

Реализовать полностью. Только совместимые добавления; оплату/цены/выдачу/merge/рефералку/stability/
логгер не ломать. Русский, деньги критичны. Дизайн фронта — как весь проект (ЧБ/Dracula/стекло).

## 1. ПРОДЛЕНИЕ ПОДПИСКИ (renewal) — повторные продажи

Юзер продлевает существующий ключ, доплачивая, вместо покупки нового.
1. Схема: `ALTER TABLE orders ADD COLUMN renew_of INTEGER` (id продлеваемого заказа; NULL у обычных).
2. db.js:
   - `renewQuote(order)` -> {days, stars} — стоимость продления = ЦЕНА этого заказа заново
     (Σ по регионам priceStars(section-по-list_type) с учётом qty/extra), days=subDays().
   - `applyRenewal(origOrderId, addDays)` — продлить: `expires_at = max(now, expires_at) + addDays*86400`
     (если истёк — от now; если активен — от текущего срока). Идемпотентность через отдельный
     renewal-заказ (см. ниже), не двойное продление.
   - createOrder уже умеет; renewal — это заказ со stars=цена, status pending, `renew_of=origId`,
     regions/qty КОПИЯ оригинала (для суммы). При оплате renewal-заказа: applyRenewal(renew_of,
     subDays), НЕ создавать новый ключ/подписку (продлеваем оригинал), пометить renewal-заказ paid.
3. bot.js: в /profile у каждого активного/истёкшего ключа кнопка «🔄 Продлить (Xдн · Y⭐)» →
   создать renewal-заказ (reserveOrder-подобно, но списывать free/bonus как обычно) → инвойс/крипта
   → successful_payment: если order.renew_of → applyRenewal(renew_of, subDays), уведомить «ключ
   продлён до DD.MM», НЕ слать новый ключ (тот же). Merge учитывает продлённый срок автоматически.
4. server.js: `POST /api/renew` {initData, orderId} → создать renewal-заказ владельца этого orderId,
   вернуть invoiceLink/crypto/free. /api/me/key — у ключа поле `canRenew:true`, `renewStars`, `renewDays`.
5. mini app: у каждого ключа кнопка «🔄 Продлить» (openInvoice/оплата). После оплаты — обновить срок.

## 2. УВЕДОМЛЕНИЯ ОБ ИСТЕЧЕНИИ (retention)

Бот сам напоминает продлить до истечения.
1. Схема: `ALTER TABLE orders ADD COLUMN notify_stage INTEGER DEFAULT 0` (0=не слали, 3=слали за 3дн,
   1=слали за 1дн, -1=слали «истёк»).
2. Новый модуль src/notify.js (require config, db) ИЛИ в inventory/index: таймер каждые ~30 мин
   (unref): найти paid|gift заказы, где до expires_at осталось ≤3 дн и notify_stage>3 (ещё не слали
   3-дневное) → отправить владельцу «⏳ Твой ключ истекает через N дн., продли», кнопка «🔄 Продлить»;
   выставить notify_stage=3; аналогично за ≤1 дн (stage 1); после истечения (stage -1) — «ключ истёк,
   продли чтобы вернуть». Не спамить (по stage). Всё try/catch, ошибки глотать, 403 blocked — молча.
   Запускать startNotifier(botApi) из index.js (при !SKIP_BOT).
3. Настройки NOTIFY_ENABLED(1), интервалы можно константами.

## 3. ПОДДЕРЖКА В БОТЕ (тикеты)

Юзер пишет в поддержку прямо в боте, админ отвечает через бота.
1. Схема: `CREATE TABLE IF NOT EXISTS tickets(id INTEGER PRIMARY KEY AUTOINCREMENT, user_id INTEGER,
   username TEXT, ts INTEGER, message TEXT, status TEXT DEFAULT 'open', admin_reply TEXT, replied_by
   INTEGER, replied_at INTEGER)`.
2. bot.js: /support (и кнопка «✍️ Написать в поддержку») → FSM «жду сообщение» → юзер пишет → создать
   ticket, отправить всем ADMIN_IDS карточку «🎫 Тикет #N от @user(id): <текст>» с кнопкой «✉️ Ответить»
   (cb `tkreply:N`) → админ жмёт, пишет ответ (ForceReply) → бот шлёт юзеру «💬 Ответ поддержки: <текст>»,
   ticket.status='answered'. Юзеру подтверждение «сообщение отправлено, ответим скоро». Антиспам: не
   больше ~5 открытых тикетов на юзера.
3. db.js: createTicket/getTicket/setTicketReply/openTicketsCount. server.js (опц.): в админ-панель
   счётчик открытых тикетов. Логировать через logAction.

## 4. «КЛЮЧ НЕ РАБОТАЕТ» — САМОПОМОЩЬ (бьёт по жалобам на стабильность)

Кнопка, которая чинит/освежает ключ без поддержки.
1. bot.js: у ключа в /profile и в выдаче кнопка «🆘 Ключ не работает» (cb `fix:<orderId>`) →
   - перевыдать АКТУАЛЬНУЮ живую подписку (buildSub уже живой + reserve → свежие живые серверы);
   - краткая инструкция: «1) удали старый ключ в приложении и вставь эту ссылку заново 2) в приложении
     выбери другой сервер из списка 3) если не помогло — жми Продлить/Поддержку»;
   - кнопки: «🔄 Обновить серверы» (перевыдать), «🌍 Сменить регион» (предложить купить/переключить),
     «✍️ Поддержка».
   - (опц.) пометить серверы этого ключа для приоритетной проверки healthcheck.
2. key.html/mini app: на странице ключа кнопка «🆘 Не работает» с той же инструкцией + «обновить».
3. Цель: юзер сам решает проблему мёртвого сервера (перевыдача даёт живые+резерв), меньше жалоб.

## Тесты (E2E — строго, деньги + продление)
- Renewal: renewQuote считает цену=повтор заказа; POST /api/renew создаёт renewal-заказ (renew_of set);
  «оплата» renewal → applyRenewal продлевает expires_at оригинала (истёкший — от now, активный — +срок),
  НОВЫЙ ключ НЕ создаётся; free/bonus применяются; повтор оплаты не двойной; merge видит новый срок.
- Notify: заказ с expires_at через 2 дня и notify_stage=0 → notifier помечает stage и «шлёт» (мок api);
  повторный проход не дублирует; истёкший → stage -1 один раз.
- Tickets: createTicket; reply flow (мок ctx) шлёт юзеру ответ, status меняется; антиспам-лимит.
- Fix: cb fix:<id> перевыдаёт живую подписку (несколько живых из-за reserve), не крашит на 0 живых.
- node --check; selftest/parse-check зелёные; всё существующее цело; инвойс на 0 не создаётся.

## Приёмка
- Продление ключа оплатой (не новый ключ); авто-напоминания до истечения; поддержка-тикеты с ответами
  админа в боте; кнопка «ключ не работает» с перевыдачей живых серверов и инструкцией. Ничего старого
  не сломано.

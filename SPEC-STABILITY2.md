# SPEC-STABILITY2 — надёжность ключей (ключ НИКОГДА не должен пропадать/переставать работать)

Проблема (подтверждена на проде): 28 регионов имеют лишь 1-2 живых сервера; при qty=1 это единая
точка отказа — сервер моргнул → ключ опустел → клиент видит «пропало»/«работает-перестаёт по кругу».
Плюс ложная геолокация CDN (КНДР = Fastly IP). Цель: сделать выдачу отказоустойчивой и точной.
Только совместимые добавления; цены/оплату/маршруты не ломать. Русский. МАКСИМАЛЬНАЯ валидация.

## 1. Конфиг (config.js + .env.example)

- `SUB_RESERVE_PER_REGION` (env, дефолт `2`) — сколько ДОПОЛНИТЕЛЬНЫХ живых серверов региона класть
  в подписку сверх купленного qty для мгновенного failover в приложении (0 = выключить).
- `MIN_ALIVE_TO_SELL` (env, дефолт `2`) — регион с меньшим числом живых серверов НЕ показывается и не
  продаётся (слишком хрупкий). Существующие заказы на такой регион продолжают отдавать что есть.
- `HEALTH_GRACE_FAILS` (env, дефолт `2`) — сервер помечается мёртвым только после стольких ПОДРЯД
  неудачных проверок (одиночный блип не убивает сервер из выдачи). Первый успех — мгновенно жив.
- `HEALTH_TLS` (env, дефолт `1`) — для tls/reality-конфигов проверять TLS-хендшейк (точнее TCP:
  ловит «порт открыт, но сервер битый» — прямой кейс «работает-перестаёт»).
- `COUNTRY_BLACKLIST` (env, дефолт `KP`) — ISO-страны, которые никогда не показываем/не продаём
  (заведомо ложная геолокация/невозможные). Список через запятую.

## 2. Схема (миграция, идемпотентно)

- `ALTER TABLE configs ADD COLUMN alive_fails INTEGER DEFAULT 0` — счётчик подряд-неудач для grace.

## 3. db.js — точная живость + отказоустойчивая выдача

- **Grace-логика** (в setAliveByHostPort или новом setHealthResult(host,port,ok)):
  - ok=true → `alive=1, alive_fails=0, alive_checked_at=now`.
  - ok=false → `alive_fails=alive_fails+1`; `alive=0` ТОЛЬКО когда `alive_fails>=HEALTH_GRACE_FAILS`,
    иначе оставить `alive=1` (grace — сервер ещё считается живым). Всегда `alive_checked_at=now`.
  - Блэклист-хостов (setAliveByHostPattern) — сразу alive=0 (без grace).
- **COUNTRY_BLACKLIST**: во ВСЕ каталог-выборки (regionsSummary, availabilityMap, configsForRegions,
  configsForRegionsQty, aliveCountForRegions) добавить `AND country_iso NOT IN (blacklist)` (+ уже есть
  `country_iso!='XX'`). Регион из блэклиста не показывается/не продаётся/не выдаётся.
- **MIN_ALIVE_TO_SELL**: regionsSummary и availabilityMap — регион в каталоге только если
  `alive_count >= MIN_ALIVE_TO_SELL` (HAVING). Хрупкие (1 живой) скрыты.
- **Резерв для failover**: `configsForRegionsQty(qtyMap, listType, {reserve})` — для каждого региона
  вернуть `min(qty + reserve, aliveCount)` ЖИВЫХ (сорт last_seen DESC, hash) — купленные + резервные
  живые того же региона для мгновенного переключения в приложении. `reserve=SUB_RESERVE_PER_REGION` по
  умолчанию (buildSub передаёт его). Дедуп сохраняется. Резерв НЕ влияет на цену/qty (это надёжность).
  - liveRowsForOrder(order) тоже применяет reserve.
- Обратная совместимость: старый вызов без reserve → reserve=0 (как раньше) — НО buildSub теперь
  всегда передаёт SUB_RESERVE_PER_REGION.

## 4. inventory.js — точная проверка (TLS) + приоритет проданных + без «моргания»

- **TLS-проверка**: helper tlsAlive(host,port,timeout) через `node:tls` (connect + 'secureConnect' →
  ok; ошибка/таймаут → false; `rejectUnauthorized:false` — нам важен факт живого TLS, не валидность
  cert). Применять для конфигов с security tls/reality (определять по uri/label или проверять всегда
  TLS при HEALTH_TLS=1, иначе TCP). Дорогой — уложиться в батч/конкурентность (≤64, ulimit 1024).
- **setHealthResult** вместо setAliveByHostPort (grace-логика §3).
- **Приоритет проданных**: hostsToCheck сначала отдаёт host:port, которые есть в АКТИВНЫХ заказах
  (paid|gift, не истёкшие) — их проверяем каждый цикл (они реально у клиентов), остальное ротацией.
  Добавить hostsSoldFirst(limit) или расширить hostsToCheck: сначала «проданные», добить ротацией.
- **Без моргания при refresh**: reconciliation (деактивация) уже гейтится «все источники ok»
  (SPEC-SOURCES). Дополнительно: upsertConfigs при UPDATE НЕ сбрасывает alive/alive_fails (уже так) —
  проверить, что refresh НЕ обнуляет живость проданных серверов.
- Канареечный сейфгард — оставить (уже есть).

## 5. server.js / bot.js — ключ НИКОГДА не «пропадает»

- /api/key, /api/me, sendDelivery: если у региона временно 0 живых — НЕ показывать «пусто/пропало»,
  а держать заказ видимым с пометкой «△ серверы временно обновляются, скоро вернутся» (partial/note уже
  есть — усилить текст, чтобы не выглядело как исчезновение). Заказ из профиля НЕ исчезает никогда
  (ordersOfUser не фильтрует по живости — подтвердить).
- buildSub/buildMerged передают reserve — в подписке всегда несколько живых на регион (failover).

## 6. Тесты (E2E — МАКСИМАЛЬНО строго, это критично)

1. node --check; selftest/parse-check зелёные; миграция alive_fails идемпотентна.
2. Grace: setHealthResult(h,false) при GRACE=2 → 1-й fail: alive остаётся 1, alive_fails=1; 2-й fail:
   alive=0; успех → alive=1, alive_fails=0. Одиночный блип НЕ убирает сервер из выдачи.
3. Резерв: регион с 5 живыми, заказ qty=1, reserve=2 → configsForRegionsQty вернул 3 живых (1+2);
   регион с 1 живым — вернул 1 (сколько есть). buildSub подписки содержит резервные.
4. MIN_ALIVE: регион с 1 живым при MIN_ALIVE=2 — НЕ в regionsSummary/availabilityMap (не продаётся);
   заказ на него всё равно отдаёт свой 1 сервер (существующий клиент не отрезан).
5. COUNTRY_BLACKLIST=KP: KP-регион отсутствует в каталоге/выдаче; заказ на KP (если есть) — не крашит.
6. TLS-health (мок node:tls или локальный TLS-сервер): tls-сервер живой→alive; TCP-открыт-но-не-TLS→
   мёртв (ловим «битый»). При HEALTH_TLS=0 — TCP как раньше.
7. Приоритет проданных: hostsToCheck при наличии активных заказов ставит их серверы первыми.
8. Ключ не пропадает: заказ на регион, у которого стало 0 живых → /api/key всё ещё возвращает заказ
   (не 404), с note «обновляются», active=true (по сроку), servers может быть 0 но ключ виден.
9. Существующее (оплата/цены/merge/free/bonus) не сломано; инвойс на 0 не создаётся. Живой boot-smoke.
   Убрать тестовые БД.

## 7. Приёмка

- Резервные серверы в каждой подписке → приложение мгновенно переключается, «перестаёт работать» уходит.
- Grace + TLS-проверка → мёртвые/битые ловятся точнее, блипы не выкидывают сервер.
- Хрупкие (1 живой) регионы скрыты из продажи; КНДР и ложные страны — вырезаны.
- Заказ/ключ НИКОГДА не исчезает из профиля (в худшем случае — «серверы обновляются»).
- Всё жёстко провалидировано; оплата/цены/merge не задеты.

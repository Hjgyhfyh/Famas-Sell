# SPEC-MERGE — объединение всех ключей в один

Задача: у клиента может быть несколько заказов (разные регионы, разные сроки). Кнопка «Объединить»
делает так, что отдельные ключи исчезают из профиля, а появляется ОДИН ключ со всеми серверами сразу.
Разные сроки окончания решаем «по-умному»: каждый регион живёт до срока СВОЕГО заказа, объединённая
ссылка не меняется, истёкшее просто выпадает. Только совместимые добавления; цены/заказы не ломать.

## 1. Идея

- «Объединённый ключ» юзера = ДИНАМИЧЕСКАЯ подписка-объединение всех его АКТИВНЫХ (paid|gift|free,
  now<=expires_at) заказов: для каждого заказа берём его qty ЖИВЫХ серверов (по SPEC-QTY/QUALITY),
  склеиваем, дедуплицируем по серверу, ребрендим. Ссылка стабильна (один токен на юзера), контент живой.
- Разные сроки: у каждого сервера — срок его заказа. Пока заказ активен — его серверы в объединённой
  подписке; истёк — выпали (остальные работают). `subscription-userinfo: expire` = МАКС срок среди
  активных заказов (чтобы клиент не считал ключ «просроченным» раньше времени). Разбивку по срокам
  показываем в профиле/на странице ключа.

## 2. Схема (миграция, идемпотентно)

- `ALTER TABLE users ADD COLUMN merged INTEGER DEFAULT 0` — включён ли режим объединения.
- `ALTER TABLE users ADD COLUMN merged_token TEXT` — стабильный токен объединённой подписки (генерится
  один раз при первом включении, util.genToken; уникален).

## 3. db.js (аддитивно)

```js
activeOrdersOf(userId) -> [order...]        // status IN(paid,gift,free-как-paid) AND now<=expires_at, свежие сверху
setMerged(userId, on) -> {merged, token}    // on=true: merged=1, при отсутствии merged_token — сгенерить и сохранить; on=false: merged=0 (token оставить)
getUserByMergedToken(token) -> user|null    // для роутинга /s/:token
mergedSummary(userId) -> {                  // для профиля/страницы
   regions:[{iso,nameRu,flag,qty,liveServers,expiresAt}], servers, expiresMax, orders:N
}
```

## 4. subscription.js — buildMerged(userId)

`buildMerged(userId) -> { lines, b64, headers, servers, expiresMax, regions }`:
- собрать `activeOrdersOf(userId)`; для каждого — его живые серверы (configsForRegionsQty по его qty,
  либо configsForRegions если qty NULL), уже отфильтрованные alive;
- ДЕДУП по каноническому серверу (host:port:uuid) — один сервер один раз, даже если куплен в двух заказах;
- ребренд фрагмента `FAMAS ⁂ <flag> <RegionRu> · до DD.MM` (срок = expires_at заказа-владельца сервера);
- headers как в §6 SPEC.md, но `subscription-userinfo: expire=<expiresMax>`, `profile-title` тот же;
- `b64` от `lines.join('\n')` (UA-gate из SPEC-HARDEN применяется на server-слое так же).
- Если активных заказов нет → пустой b64 (как истёкший).

## 5. server.js — роутинг и API

- `GET /famas/s/:token` — расширить резолвинг: если token = заказный → как сейчас; если token =
  `getUserByMergedToken` → `buildMerged(user.id)` (тот же UA-gate/заголовки). QR `/qr/:token.svg` и
  страница `/k/:token` — тоже поддержать merged-токен (страница ключа показывает объединённый ключ).
- `GET /famas/api/me` — если `user.merged` и есть merged_token: вернуть ЕДИНЫЙ ключ:
  `{merged:true, key:{token, page, sub, servers, expiresMax, regions:[{iso,nameRu,flag,qty,expiresAt}]}}`
  вместо списка orders (или orders:[] + merged-объект). Если merged выключен — как сейчас (список).
  Плюс всегда отдавать `canMerge` (есть ≥2 активных заказа) и текущее состояние `merged`.
- `POST /famas/api/merge` body `{initData, on:bool}` — validateInitData → `db.setMerged(user.id,on)` →
  вернуть новое состояние + (если on) merged key. no-store.
- `GET /famas/api/key/:token` — поддержать merged-токен (вернуть объединённые regions с их сроками,
  servers, active=есть ли активные заказы).

## 6. bot.js

- `/profile`: если у юзера ≥2 активных заказа — кнопка «🧩 Объединить всё в один ключ» (cb `merge:on`);
  если merged включён — показать ОДИН объединённый ключ (кнопка «Ключ» → страница merged, «Подписка»
  копирует merged sub) + разбивку «внутри: 🇩🇪 Германия ×2 до 05.08 · 🇳🇱 …», и кнопку «Разъединить»
  (cb `merge:off`). При merged=0 — список как сейчас.
- Выдача при покупке (sendDelivery): если у юзера merged включён — в конце добавить строку «добавлено в
  твой объединённый ключ» и кнопку на merged-страницу (новый заказ автоматически влит, т.к. merged =
  все активные заказы). Индивидуальную ссылку тоже показать (на случай если merged off).
- Уведомления/тексты — русские, ЧБ-стиль.

## 7. mini app (МОИ КЛЮЧИ)

- Если `me.canMerge` и не merged — заметная кнопка «🧩 Объединить всё в один ключ» (POST /api/merge on) →
  после: список ключей сворачивается в ОДИН объединённый (анимация), показываем его (аватар-квитанция:
  все регионы с флагами ×qty и их сроки, «серверов: N», кнопки Открыть/Копировать/QR). Кнопка
  «Разъединить» возвращает список.
- Если merged включён — сразу показываем один объединённый ключ (индивидуальные скрыты). Разные сроки —
  строкой у каждого региона «до DD.MM».
- Стиль/темы/анимации как везде; тексты русские.

## 8. Тесты

- миграция merged/merged_token идемпотентна.
- setMerged генерит стабильный token (не меняется при повторном on/off); activeOrdersOf исключает
  истёкшие; buildMerged дедуплицирует серверы, expire=max, регионы со своими сроками; пустой при 0
  активных.
- /s/<mergedToken> отдаёт объединённую подписку (все регионы, живые, дедуп); /api/me при merged=1
  отдаёт единый ключ и canMerge; POST /api/merge переключает; /api/key/<mergedToken> работает.
- Новый заказ после включения merged автоматически в объединённой подписке; истёкший заказ выпадает,
  остальные остаются.
- существующие индивидуальные ключи/оплата не сломаны. Убрать тестовые БД.

## 9. Приёмка

- Кнопка объединяет все ключи в один; в профиле остаётся 1 ключ со всеми регионами; разные сроки
  корректны (каждый регион до своего срока, ссылка одна и живая); можно разъединить; новые покупки
  автоматически вливаются.
